# 🚀 [발표 자료] 1비트 LLM의 한계 극복 및 소형 어텐션 신경망을 통한 픽셀 아트 컴파일러 구축기

## 1. 프로젝트 배경 및 문제 정의

* **목표:** 자연어 명령(예: "빨간 정사각형을 그려줘")을 받아 정해진 규칙의 압축 프로토콜(텍스트)로 번역하는 **픽셀 아트 컴파일러** 개발.
* **초기 시도:** 고성능 인프라(NVIDIA A100) 환경에서 1비트 양자화 모델(BitNet 1.58b)을 활용한 LoRA 파인튜닝 진행.
* **초기 결과 및 문제점:**
* **OOM(Out Of Memory) 발생:** 초기 배치 사이즈 오버헤드로 인한 GPU 메모리 폭발 ➡️ `gradient_accumulation_steps` 및 `gradient_checkpointing` 최적화로 해결.
* **포맷 붕괴 (Hallucination):** 훈련 종료 후 모델이 `[L1]` 규칙 대신 `r"0"0"0"...` 같은 국적 불명의 파이썬 스타일 문자열을 출력하며 최종 렌더링 실패.



---

## 2. 본질적인 원인 분석

1. **1비트 가중치의 표현력 한계:** 극단적인 가중치 상태($-1, 0, 1$)로 인해, 사전 학습 단계에서 굳어진 거대한 영어 텍스트 관성을 소량의 데이터(320개)와 얇은 LoRA 회로로 꺾기 역부족.
2. **기존 토크나이저(BPE)의 한계:** 프로토콜 문자(`[`, `L`, `1`, `]`)를 개별 텍스트 토큰으로 잘게 쪼개어 인식하므로, 토큰 체인이 길어질수록 어텐션(Attention)이 문맥 간의 인과관계를 잃고 손실 발생.

---

## 3. 새로운 가설 세우기 & 설계 변경 (POC 단계 진입)

거대 모델에 무작위로 매달리기 전, 핵심 가설을 검증하기 위한 **소형 전용 인공 신경망(Toy Model)** 아키텍처로 방향 전면 수정.

* **가설 1 (토큰 다이어트):** 개행 문자나 행 태그를 모두 제거하고 $16 \times 16 = 256$ 픽셀을 하나의 단층 스트림으로 취급하여 어텐션의 연산 부담을 최소화한다.
* **가설 2 (출력물 자체의 토큰화):** `51W`, `10R`과 같이 **`[길이][색상]` 조합 자체를 쪼개지지 않는 하나의 고유 토큰**으로 사전에 선언하여 포맷 붕괴를 물리적으로 차단한다.
* **가설 3 (교사 강요 지도 학습):** CNN 등 비전 신경망 없이, 오직 시퀀스 간의 관계를 매핑하는 **Seq2Seq + Luong Attention** 구조와 **교사 강요(Teacher Forcing)** 학습법으로 픽셀 정렬을 통제한다.

---

## 4. 파이프라인 구현 및 검증 과정

### 🧱 데이터 파이프라인 (`pixel_data_generator.py` & `pixel_dataloader.py`)

* 5가지 색상(R, B, G, Y, K)과 6가지 도형(정사각형, 삼각형, 십자가 등)을 조합한 청정 데이터셋(320개) 자동 빌드.
* 단층 스트림 RLE(Run-Length Encoding) 압축기 및 고유 보카 사전(Vocab Size: 107) 구축 완료.
* 가변 길이의 시퀀스를 가장 긴 타겟 기준으로 가로 정렬하는 패딩 콜레이트(`collate_fn`) 적용.

### 🧠 모델 및 학습 파이프라인 (`pixel_train.py` & `pixel_inference.py`)

* PyTorch 순정 기능을 이용해 **Linear 변환 기반 Luong Attention 레이어** 및 **Encoder-Decoder(GRU)** 모델 구축.
* CrossEntropyLoss(ignore_index=0) 및 AdamW 옵티마이저를 활용하여 40 Epoch 지도 학습 진행 ➡️ **Loss가 0에 가깝게 완벽 수렴**.
* 추론 단계에서는 교사 강요를 끄고 자가 예측(Autoregressive) 방식으로 구동하여 보안 가드(Unpickling/Safe Globals 라이브러리 이슈) 통과 후 최종 가중치 로드 성공.

# 🎨 AI 기반 16x16 픽셀 아트 컴파일러 개발 프로젝트 보고

## 📌 1. 프로젝트 개요
* **목표**: 자연어 프롬프트(Input)를 받아 커스텀 픽셀 프로토콜(Output)을 생성하고, 이를 터미널에 실시간 렌더링하는 엔드투엔드(End-to-End) AI 서비스 구축.
* **아키텍처**: PyTorch 기반 Seq2Seq (Encoder-Decoder) 모델 + 커스텀 ANSI 256 RGB 렌더러 모듈.

---

## 🔍 2. 주요 문제 해결 및 고도화 이력

### 🛠️ [이슈 1] 프로토콜 파싱 에러로 인한 그리드 밀림 현상
* **현상**: 특정 프로토콜 전개 시 `1L2W` 또는 `1L16W`와 같이 줄바꿈 기호(`1L`)와 픽셀 토큰이 공백 없이 붙어버려 렌더러가 인식하지 못하고 픽셀이 누락됨 (256칸 미만으로 그리드가 깨짐).
* **원인**: 대괄호 제거 및 정규식 확장 과정에서 문자열이 결합하는 예외 케이스 발생.
* **해결**: 토큰화(`split()`) 직전, `1L` 문자열 앞뒤로 공백을 강제 주입(`replace("1L", " 1L ")`)하는 철벽 방어 로직을 구현하여 16x16 격자 무결성 확보.

### 🎨 [이슈 2] 터미널 컬러 매핑 왜곡 및 오매핑
* **현상**: 핑크색 토큰(`H`)이 빨간색(`R`)으로 잘못 매핑되어 있었고, 표준 ANSI 8/16 컬러 사용으로 인해 터미널 테마별 색상 왜곡 발생.
* **해결**: 표준 컬러 코드를 버리고 **16진수 기반 고해상도 RGB 256 컬러 맵**으로 전면 개편. 핑크색(`H`)의 고유 독립 색상을 확보하고 순백색(`W`) 배경을 강제 고정하여 쨍한 색감 구현.

### 🧠 [이슈 3] "make a red triangle" 특정 단어 조합의 가중치 간섭
* **현상**: `generate a red triangle`이나 `make a green triangle`은 완벽히 수행하나, 유독 `make a red triangle` 입력 시 하단에 주황색(`O`) 픽셀이 튀는 환각(Hallucination) 현상 발생.
* **원인**: 데이터셋 자체는 무결하나, `make`와 `red`라는 강한 토큰이 결합하면서 모델 내부 뉴런 공간에서 `orange` 가중치 경로와 혼선(Embedding Interference)을 일으킴.
* **해결 (임시)**: CLI 추론 엔진 단에서 해당 프롬프트를 감지하여 정상 경로(`generate a red...`)로 가로채는 인터셉터 우회 패치 적용.

## 🔮 4. 한계점 및 향후 고도화 로드맵 (Next Action)

현재 모델은 단어 사전(Vocabulary)의 크기가 작고 색상/형태 간의 '개념적 독립 분리'가 미숙하여, 등록되지 않은 단어 입력 시 주황색 노이즈가 출력되거나 완벽한 철자를 입력해야만 반응하는 한계가 있습니다. 이를 해결하기 위해 다음 단계로 진입합니다.

### 1️⃣ WordPiece / BPE 토크나이저 도입
* 현재의 통짜 단어 매칭 사전을 탈피, 형태소/서브워드 단위로 쪼개는 BPE 알고리즘 도입.
* `checkerboard` 같은 단어를 `check` + `##board`로 인식하게 만들어 오타 대응력과 미학습 단어(`<UNK>`) 방어력 극대화.

### 2️⃣ 단어 사전(Vocabulary)의 카테고리별 선제 확장
* 데이터셋에 없는 단어라도 다양한 색상 표형(crimson, cyan 등)과 기하학적 형태(diamond, border 등)의 기본 사전을 미리 빌드 단계에 주입하여 임베딩 공간의 베이스를 확장.

### 3️⃣ 매크로 기반 대량 데이터 증강 (Data Augmentation)
* 현재 매크로 생성 코드를 고도화하여 **[동사 × 색상 × 형태 × 스타일]**의 4개 축 순열 조합을 자동으로 셔플하는 알고리즘 구축.
* 최소 1만~5만 개 이상의 문장 조합으로 이루어진 대량의 데이터셋(`pixel_model_v5.pt`)을 구축하여, 색상과 형태 뉴런이 완전히 독립적으로 어텐션(Attention)을 갖도록 리트레이닝 진행.


> "챗봇 모델에서 입력한 프롬프트를 이미지로 출력할 수 있을까?" -> ascii 아트 기반 출력을 고려 -> 필요한 정보가 많길래 더 압축하기 위해 색상과 길이만 이용하여 표현하자

> bitnet의 파인튜닝이이 너무 어려워서 다른 소형 모델에 파인튜닝을 적용하기로 결정함 -> "다른 모델에서 내가 기획한 문자열 압축 방식의 토큰 묶음 출력 방식이 작동하나?" 의문이 발생 -> 검증을 위해 커스텀 데이터 셋부터 모델 학습 및 추론까지 구현

> 세부 로직에 대해서는 문자열 압축 알고리즘에서 아이디어를 얻어 커스텀 문자열 압축 방식을 도입함

- [{색상}{길이}]의 토큰을 생성 
- [Re{횟수}][ {색상}{길이} ... ] -> 횟수 만큼 다음에 오는 [] 내부의 토큰을 반복함 -> 이미지 패턴 학습용
