# 🚀 픽셀 아트 컴파일러 (Pixel Art Compiler)

자연어 프롬프트(Input)를 받아 커스텀 압축 프로토콜(Output)로 변환하고, 이를 터미널 환경에 실시간 픽셀 아트로 렌더링하는 AI 기반 엔드투엔드(End-to-End) 컴파일러 프로젝트입니다.

---

## 💡 1. 프로젝트 기획 및 철학

본 프로젝트는 "챗봇 모델에서 사용자가 입력한 프롬프트를 이미지로 직접 출력할 수 있을까?"라는 호기심에서 출발했습니다.

* **압축 프로토콜의 탄생:** 초기에는 ASCII 아트 출력을 고려했으나, 프롬프트 대비 표현해야 할 정보량이 너무 많았습니다. 이를 극복하기 위해 **'색상'과 '길이'만을 이용한 커스텀 문자열 압축 알고리즘**을 기획했습니다.
* **가설 검증을 위한 우회:** 본래 1비트 LLM(BitNet 1.58b) 환경에서 파인튜닝을 시도했으나 극심한 메모리 오버헤드와 포맷 붕괴에 부딪혔습니다. 이에 거대 모델에 매달리기 전, "내가 기획한 압축 프로토콜과 토큰 묶음 출력 방식이 실제 모델에서 작동하는가?"를 먼저 검증하기 위해 소형 전용 인공 신경망(Toy Model)으로 노선을 변경하여 데이터셋 구축부터 학습, 추론까지 전체 파이프라인을 직접 구현하게 되었습니다.

---

## ⚙️ 2. 핵심 알고리즘: 커스텀 RLE 프로토콜

일반 텍스트의 나열을 넘어, 이미지 압축 알고리즘(RLE)에서 착안한 독자적인 토큰화 방식을 사용합니다.

* `[{색상}{길이}]` : 기본 픽셀 연속 출력 (예: `R10` ➡️ 빨간색 10칸)
* -> `{길이}{색상}` : 구조로 변경 (예: `10c224` ➡️ 빨간색 10칸)
* `[Re{횟수}][ {색상}{길이} ... ]` : 특정 구간(패턴)을 횟수만큼 반복 (이미지 패턴 학습용)
* `[X{횟수}]` : 횟수만큼 Y축(줄) 변경

```text
=================== [⚙️ Automated Build Pipeline] ===================

   1️⃣ Data Gen        2️⃣ Tokenizer       3️⃣ Split & Build

        │                  │                  │
        v                  v                  v
 [dataset_history] [tokenizer_history] [dataset_history]

```

## 📂 4. 프로젝트 디렉토리 구조

프로젝트는 자동화된 버전 관리와 모듈화된 파이프라인으로 구성되어 있습니다.

BITNET-ASCII-COLORIZER/
├── dataset_history/                # 파이프라인 버전별 생성 데이터셋(total, train, val, test) 아카이브
├── models_history/                 # 학습 및 전수 검증이 완료된 트랜스포머 가중치(.pt) 아카이브
├── tokenizer_history/              # Input BPE + Output 스페셜 토큰 통합 사전(.json) 아카이브
├── logs/                           # [격리 관리] 공정별 상세 로깅 폴더 및 pipeline.log 통합 관제
│   ├── history/                    # 디렉토리 구조 변경 전 로그
│   ├── data_generator/             # 텍스트-프로토콜 합성 로그
│   ├── tokenizer_trainer/          # BPE 어휘집 빌드 로그
│   ├── dataset_splitter/           # 8:1:1 데이터 분할 비율 및 유효성 로그
│   ├── train/                      # 트랜스포머 학습 Epoch/Loss 지표 로그
│   └── evaluate/                   # 전수 검증 결과 및 시각화 오답 노트(_error_analysis.log)
├── build.py                        # 🚀 실시간 스트리밍 제어 기반 전체 파이프라인 자동화 빌드 마스터 (버전 자동 갱신)
├── pixel_config.py                 # 중앙 집중식 파일 경로 바인딩 및 히스토리 버전 주입 모듈
├── pixel_data_generator.py         # 수식형 룰셋 + 에셋 연동 자연어-프로토콜 매칭 데이터셋 생성기
├── pixel_deserializer.py           # PNG 이미지 바이너리를 픽셀 프로토콜 토큰 데이터로 파싱하는 코어 엔진
├── train_tokenizer.py              # 통문장 출력 토큰을 보호하는 커스텀 BPE 토크나이저 학습기
├── split_dataset.py                # 데이터 오염을 방지하는 정밀 8:1:1 3비율 데이터셋 분할기 (Non-zero 에러 제어)
├── pixel_train.py                  # Seq2Seq 기반 비트넷/트랜스포머 분류 모델 가중치 훈련 스크립트
├── evaluate_model.py               # 256색 이모지 디코딩 맵 기반 미공개 테스트셋 전수 검증 및 오답노트 생성기
├── pixel_inference.py              # 🚀 학습된 가중치 모델 기반 사용자 인터랙티브 CLI 실시간 컬러라이징 추론 엔진
├── pixel_renderer.py               # RGB 256색 터미널 탈출 시퀀스(Escape Sequence) 기반 그래픽 렌더링 엔진
├── extractor.py                    # 스프라이트 시트(SpriteSheet) 이미지 소스를 개별 슬라이스(이름.png)로 자동 추출
├── pixel_logger.py                 # 공정 격리형 멀티 헨들러 파일/터미널 로깅 유틸리티
└── pixel_versions.json             # (Auto-generated) 파이프라인 빌드 성공 이력 및 릴리즈 버전 트래킹 인덱스

## 🔍 5. 트러블슈팅 및 구조적 진화 (Journey)

### 🚨 라벨 데이터 혼선 방지를 위한 아키텍처 변경

* **문제:** 모델이 다음 토큰을 예측해서 생성하려는 Auto-Regressive 방식의 특성상, 프로토콜 구조가 섞이거나 파괴되는 환각(Hallucination) 문제가 발생했습니다. (이미지와 매핑된 토큰은 그 자체로 완전한 데이터여야 함)
* **해결:** Many-to-One 문제를 해결하기 위해 **다중 클래스 분류 모델**로 구조를 일시 변경했습니다. Output 문자열 자체를 쪼개지지 않는 스페셜 토큰으로 통째로 주입하여 무결성(불변성)을 확보했습니다.

### 🚨 프로토콜 파싱 오류 및 렌더링 왜곡

* **문제:** `1L2W`와 같이 줄바꿈 기호와 픽셀 토큰이 붙어 16x16 그리드가 붕괴되거나, 기존 ANSI 16 컬러 환경에서 색상(특히 핑크/레드)이 왜곡되는 현상 발생.
* **해결:** 토큰화 직전 강제 공백 주입 방어 로직 추가 및 **16진수 기반 고해상도 RGB 256 컬러 맵**(rgb -> 3:3:2 비트 구조로 할당)으로 렌더링 엔진 전면 개편.

### 🚨 임베딩 가중치 간섭 현상

* **문제:** `make a red triangle` 입력 시 'red'와 'make'의 가중치 간섭으로 인해 엉뚱한 주황색 노이즈 픽셀이 출력됨.
* **해결:** CLI 추론 인터셉터를 통해 우선 우회 패치를 적용하였으며, 근본 해결을 위해 대규모 데이터 증강 및 BPE 토크나이저 도입을 준비 중입니다.

## 💻 6. 사용 방법 (Quick Start)

### 1) 이미지에서 토큰 직접 추출

특정 이미지에서 압축 프로토콜을 뽑아내려면 `extractor.py`를 활용합니다.
디렉토리 루트에 이미지 파일을 배치한 후 코드를 규격에 맞게 수정하여 실행하세요.

```bash
python extractor.py

```

### 2) 데이터셋 생성 및 모델 빌드 (One-Click)

학습 파이프라인 전체를 가동합니다. 실행 시 버전이 자동으로 업데이트되며, 산출물들은 `_history` 폴더에 안전하게 저장됩니다.

```bash
python build.py

```

### 3) 픽셀 컴파일러 추론 (CLI 실행)

빌드가 완료되면 인터랙티브 추론 엔진을 띄워 자연어로 이미지를 생성할 수 있습니다. (`exit`, `quit`, `q`, `종료`로 종료)

```bash
python pixel_inference.py

```

## 🚀 7. 향후 고도화 로드맵 (Next Steps)

현재의 프로토타입(다중 클래스 분류 방식)이 성공적으로 작동함을 확인했으므로, 모델의 지능을 한 단계 더 끌어올리는 작업을 진행합니다.

1. **의미적 구조 생성 모델로의 회귀:** 단순히 정해진 다중 클래스를 분류하는 방식을 넘어, **실제 텍스트의 의미를 분석하여 구조에 맞는 픽셀 토큰을 스스로 생성하는** 완벽한 생성형(Generative) 모델로 발전시킵니다.
2. **WordPiece / BPE 토크나이저 고도화:** 미학습 단어(`<UNK>`)에 대한 방어력을 극대화하고 오타 대응력을 높입니다.
3. **매크로 기반 대량 데이터 증강:** [동사 × 색상 × 형태 × 스타일]의 순열 조합을 자동으로 셔플하여 수만 개의 데이터를 구축합니다.
4. **LLM 이식:** 위 과정에서 확보된 기술력과 데이터를 바탕으로, Qwen 등의 거대 언어 모델 임베딩 레이어에 커스텀 RLE 토큰을 확장/주입하는 최종 목표로 나아갑니다.
