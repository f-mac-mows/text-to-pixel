# 🚀 픽셀 아트 컴파일러 (Pixel Art Compiler)

자연어 프롬프트(Input)를 분석하여 격자 패턴 기반의 커스텀 압축 프로토콜(Output) 토큰 스트림을 스스로 생성하고, 이를 터미널 환경에 실시간 픽셀 아트로 렌더링하는 AI 기반 엔드투엔드(End-to-End) 컴파일러 프로젝트입니다.

---

## 💡 1. 프로젝트 기획 및 철학

본 프로젝트는 "챗봇 모델이 사용자가 입력한 프롬프트를 별도의 무거운 이미지 파일 생성 공정 없이, 압축 텍스트 프로토콜만으로 터미널에 직접 생성·렌더링할 수 있을까?"라는 호기심에서 출발했습니다.

* **가설 검증과 경량 구조 채택:** 본래 BitNet 1.58b 기반 파인튜닝을 시도했으나 메모리 오버헤드와 포맷 붕괴에 부딪혔습니다. 이에 거대 모델 적용 전, "수식화된 압축 프로토콜 시퀀스를 가중치 기반 모델이 유기적으로 생성 가능한가?"를 검증하기 위해 **초소형 전용 인코더-디코더(Seq2Seq) 트랜스포머**를 설계했습니다.
* **성공적인 가설 검증:** 20만 개 규모의 대량 증강 데이터셋과 하이브리드 아키텍처를 통해, 미공개 프롬프트에서도 높은 정확도로 의도를 이해하고 픽셀 아트를 '생성(Generation)'해내는 컴파일 메커니즘을 입증했습니다.

---

## ⚙️ 2. 핵심 알고리즘: 신형 격자 패턴 RLE 프로토콜

기존의 동적 반복 패턴(`[Re{num}]`) 방식은 오토레그레시브 추론 특성상 뒤로 갈수록 오차가 누적되어 전체 그리드가 붕괴되는 잠재적 포맷 위험성이 존재했습니다. 이를 해결하기 위해 **정적 패턴 매핑 기법**으로 프로토콜을 전면 개편했습니다.

* `p{길이}_{색상ID}` : 단일 색상 연속 스캔 (예: `p10_224` ➡️ 224번 색상 10칸 연속)
* `p{반복횟수}_{색상ID_A}_{색상ID_B}` : 2도 색상 교차 패턴(체크무늬/격자) 표현 (예: `p3_000_255` ➡️ 000과 255번 색상이 3쌍 교차 출력)
* `1X` : Y축(줄바꿈) 변경 및 16x16 해상도 그리드 정렬 지시자

---

## 🏗️ 3. 파이프라인 및 아키텍처 구조도

본 모델은 **인코더 4레이어, 디코더 6레이어, 임베딩 256차원**으로 설계된 고밀도 멀티태스크 구조입니다. 입력층은 **Text BPE**, 출력층은 **Pixel WordLevel**로 어휘 사전을 분리하여 가중치 교차 오염을 원천 차단했습니다.

```text
[자연어 입력 (Text)] ──> [Text BPE (입력층)] ──> [Encoder (4L) / Decoder (6L)] ──> [Pixel WordLevel (출력층)] ──> [렌더링 엔진]

======================================= [⚙️ Automated Build Pipeline] =======================================

   1️⃣ Data Gen & Augment          2️⃣ Tokenizer (Dual)         3️⃣ Split & Build
 ┌──────────────────────┐    ┌──────────────────────┐    ┌──────────────────────┐
 │ pixel_data_          │    │  train_tokenizer.py  │    │                      │
 │ generator.py         │───>│                      │───>│  split_dataset.py    │
 │  (Rotate/Flip 증강)   │    │  ├─ Text: BPE        │    │                      │
 │  (~200,000 Rows)     │    │  └─ Pixel: WordLevel │    └──────────┬───────────┘
 └──────────┬───────────┘    └──────────┬───────────┘               │
            │                           v                           v
            v                  [tokenizer_history]         [dataset_history]
   [dataset_history]          (pixel_text_v0.json)          (Train/Val/Test)
     (Total JSONL)            (pixel_pixel_v0.json)                 │
                                                                    │
   5️⃣ Eval                  4️⃣ Train (Multi-Task)                    │
 ┌──────────────────────┐    ┌──────────────────────┐               │
 │                      │    │  pixel_train.py      │               │
 │  evaluate_model.py   │<───│  ├─ Enc: 4 Layers    │<──────────────┘
 │                      │    │  └─ Dec: 6 Layers    │
 └──────────────────────┘    └──────────┬───────────┘
                                        │
                                        v
                                 [models_history]
                                  (Model Weights)

```

## 📂 4. 프로젝트 디렉토리 구조

```text
BITNET-ASCII-COLORIZER/
├── dataset_history/                # Rotate, Flip 등으로 20만 개까지 확장된 버전별 데이터셋 아카이브
├── models_history/                 # Enc 4L / Dec 6L 기반 트랜스포머 가중치(.pt) 아카이브
├── tokenizer_history/              # [2원화] Input Text(BPE) 및 Output Pixel(WordLevel) 개별 어휘 사전 아카이브
├── logs/                           # 공정 격리형 상세 로깅 폴더 및 관제 로그
├── build.py                        # 실시간 스트리밍 제어 기반 전체 파이프라인 자동화 빌드 마스터
├── pixel_config.py                 # 중앙 집중식 파일 경로 바인딩 및 히스토리 버전 주입 모듈 (PixelPaths)
├── pixel_data_generator.py         # 데이터 증강(회전, 대칭 등)이 통합된 대규모 합성 데이터 생성기
├── pixel_deserializer.py           # [Core] 신형 p{count}_{colors} 및 1X 조합 매트릭스 직렬화 엔코더/디코더
├── train_tokenizer.py              # 자연어용 BPE와 프로토콜용 WordLevel 사전을 독립 구축하는 학습기
├── split_dataset.py                # 데이터 오염을 방지하는 정밀 8:1:1 3비율 데이터셋 분할기
├── pixel_train.py                  # 멀티태스크 Seq2Seq 기반 트랜스포머 모델 훈련 스크립트
├── evaluate_model.py               # 미공개 테스트셋 전수 검증 및 오답노트 생성기
├── pixel_inference.py              # 학습된 가중치 모델 기반 사용자 인터랙티브 CLI 실시간 추론 엔진
├── pixel_renderer.py               # RGB 256색 터미널 탈출 시퀀스(Escape Sequence) 기반 그래픽 렌더링 엔진
└── pixel_versions.json             # 파이프라인 빌드 성공 이력 및 릴리즈 버전 트래킹 인덱스

```

## 🔍 5. 트러블슈팅 및 핵심 인사이트 (Journey)

### 🚨 `[Re{num}]` 동적 루프의 불안정성과 포맷 파괴 현상

* **문제:** 초기 프로토콜인 `[Re{횟수}][ 패턴 ]` 구조는 Auto-Regressive 모델이 학습을 진행할수록 디코딩 컨텍스트가 미세하게 어긋났을 때 토큰 시퀀스 전체가 도미노처럼 무너지는 치명적인 위험성이 발견되었습니다.
* **해결:** 격자 및 체커보드 패턴을 사전에 탐지하여 `p{반복}_{colorA}_{colorB}` 형태로 규격화된 정적 토큰을 출력하도록 `PixelDeserializer`를 전면 개편하여 완벽한 포맷 무결성을 확보했습니다.

### 🚨 초소형 모델의 한계와 데이터 스케일링의 힘

* **문제:** 임베딩 256차원의 아주 작은 인코더-디코더 모델 구조 특성상, 모델의 파라미터 캐파(Capacity) 부족으로 인한 한계가 우려되었습니다. 또한 Seq2Seq 고유의 구조적 특성으로 인해 학습 속도가 정체되는 병목이 존재했습니다.
* **해결:** 데이터셋을 20만 개 수준으로 대규모 증강(Data Augmentation)하고 정제 룰을 고도화하자, 모델 크기가 작음에도 불구하고 프롬프트 선행 이해도와 픽셀 출력 품질이 비약적으로 상승하는 것을 확인했습니다. 즉, 구조적 한계를 **양질의 데이터 스케일**로 극복해 냈습니다.

---

## 🚀 6. 향후 고도화 로드맵: SLM / LLM 파인튜닝으로의 전이

본 프로젝트를 통해 "정제된 데이터셋과 명확한 RLE 프로토콜 레이아웃만 있다면 모델이 프롬프트를 시각 아트로 컴파일할 수 있다"는 사실이 성공적으로 검증되었습니다.

1. **SLM / LLM Fine-Tuning으로의 패러다임 전환:** 초소형 단독 Encoder-Decoder 구조의 느린 학습 속도와 지능적 한계를 극복하기 위해, 이미 사전 학습된 대형 모델(Qwen, Llama, Gemma 등)에 본 프로젝트의 20만 개 고품질 데이터셋을 이식합니다.
2. **비용 효율성 확보:** 대형 인프라를 바닥부터 빌드하는 것보다, 기본 정렬/문맥 이해도가 탑재된 sLLM 환경에서 파인튜닝을 진행하는 것이 학습 수렴 속도 및 비용 측면에서 훨씬 더 경제적이고 강력한 결과물을 낼 수 있음을 확인했기에 차세대 엔진은 **상용 sLLM 기반 어댑터/파인튜닝** 구조로 확장합니다.
